# India Heatwave Severity & Anomaly Detection System

React + Vite + TypeScript + Tailwind + Recharts + Leaflet frontend, FastAPI + pandas + scikit-learn backend.

> **Data source: Synthetic Demo Data.** `india_heatwave_anomaly_dataset.csv` (58,440 rows, 20 cities, 2018-01-01 to 2025-12-31)
> is not real historical weather. Its severity, anomaly and risk columns were generated by rules. Nothing here is an official warning.

## Run on macOS

Needs Python 3.10+ and Node 18+.

```bash
# Terminal 1: backend
cd backend
python3 -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt
python -m app.ml            # optional: retrain + re-evaluate (about 3 min). Trained artifacts are already included.
uvicorn app.main:app --reload --port 8000

# Terminal 2: frontend
cd frontend
cp .env.example .env
npm install
npm run dev                 # http://localhost:5173
```

API docs: http://localhost:8000/docs. Tests: `cd backend && pytest -q`.
If artifacts are missing, the backend trains once on first start (about 3 min) and caches them in `backend/artifacts/`.

## Pages
- **Map**: all 20 cities from dataset lat/lon, colour = peak severity (or mean risk score) in the selected range, dashed ring = Isolation Forest flags. Popup shows temps, risk, labelled anomalies, IF flags, agreement.
- **Analytics**: temperature trend, city risk comparison, monthly heatwave days, severity distribution, humidity vs temperature, correlations. All driven by the date / region / city filters.
- **Anomalies**: Isolation Forest vs dataset `is_anomaly` labels (precision, recall, F1, ROC-AUC, PR-AUC, confusion matrix, recall per anomaly type) and a paginated record table.
- **SVM model**: held-out metrics, baselines, confusion matrix, per-class table, leakage audit, limitations, and a small predict form.
- **Alerts**: historical replay of rows at or above a chosen severity or flagged by Isolation Forest. Simulated, not live.

## Methods
**Validation** (`app/data.py`): required columns, duplicate city-dates, lat/lon bounds, unknown severity labels, missing values. `anomaly_type` is empty by design for normal rows.

**Severity classifier** (`app/ml.py`): stratified 80/20 split; `StandardScaler` + RBF `SVC` in one pipeline (scaler fit on train only); `class_weight="balanced"`; GridSearchCV over C and gamma, 5-fold macro-F1, on a train-only subsample; evaluation on the untouched test set against a linear SVM and a majority-class baseline.

**Why temperature is excluded.** In this dataset, severity is exactly a threshold on `max_temp_c` (37 / 40 / 42 / 45 C). Giving the SVM temperature columns yields about 0.95 macro-F1 by re-learning that rule. That figure is shown as a *leakage audit* and nowhere else. The real model uses min temp, humidity, rainfall, wind, UV, location and day-of-year, and its scores are low. That is the honest result.

**Isolation Forest**: features are standardised deviations from each city's own calendar-month median/std; contamination is fixed at 2% (not tuned on labels, though it is close to the ~2.0% label rate). It is unsupervised; labels are only used afterward for comparison.

## Latest results (seed 42; rerun `python -m app.ml` to regenerate)
| | macro-F1 |
|---|---|
| RBF-SVM (temperature-free) | 0.302 |
| Linear SVM | 0.298 |
| Always "Low" | 0.189 |
| Leakage audit (with temperature) | 0.952 (not meaningful) |

Isolation Forest vs labels: precision 0.373, recall 0.374, F1 0.374, ROC-AUC 0.923. Recall by type: Rainfall 98%, Wind 37%, Temperature spike 13%, Humidity 10%.

## Limitations
- Synthetic data: scores measure recovery of generation rules, not real-world skill.
- Severe (48) and Extreme (10) test samples are tiny, so their metrics are very noisy.
- Random split on daily records; neighbouring days may land in train and test. Single seed, no confidence intervals.
- Isolation Forest detects unusual observations; it does not forecast weather.
- RBF-SVM beats the linear baseline only marginally here; do not read much into the gap.

## Using a different CSV
Replace `backend/data/india_heatwave_anomaly_dataset.csv` with a file containing the columns listed in `REQUIRED` in `backend/app/config.py`, delete `backend/artifacts/*`, then run `python -m app.ml`. Validation errors name missing columns.
